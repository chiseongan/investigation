# 성능 점검

## 지금까지 확인한 것 (자동)
| 항목 | 결과 |
|---|---|
| 배포 크기 | 약 0.34MB (JS 303KB / gzip 85KB, CSS 25KB, 아이콘 포함) — 목표 5~10MB 이하 |
| 애니메이션 속성 | 모든 `@keyframes`·`transition` 이 `transform`/`opacity` 만 사용 (마지막 점검 때 HUD 숫자 튀는 효과의 `color` 를 제거) |
| 타이머·루프 | `setInterval` 없음. 하루 타이머와 걷기는 `requestAnimationFrame`, 메신저 말풍선은 CSS `animation-delay` |
| 폰트 | 번들 없음. 시스템 폰트(Pretendard 가 설치돼 있으면 사용) |
| 이미지 | 임시 SVG 스프라이트(수 KB). 실제 그림으로 바꿀 때 WebP/스프라이트 시트 사용 |
| 접근성 | 모든 버튼 높이 44px 이상, `prefers-reduced-motion` 지원, 소리 없음 |

## 직접 확인해야 하는 것 (이 환경에서는 브라우저를 열 수 없어서 못 했습니다)
1. **저사양 기기에서 끊김**: Chrome 개발자 도구 → Performance → CPU **4× / 6× slowdown** 으로 아래 장면을 5분간 돌려 보세요.
   - 10×10 교실에서 확대·축소·드래그, 캐릭터 걷기
   - 수요일 단톡방(말풍선이 연속으로 나옴)
   - 엔딩의 타임라인 스크롤
   - 프레임이 눈에 띄게 끊기면 알려 주세요. 후보: 교실의 가구·캐릭터 DOM 수, 줌 중 레이어 수.
2. **실제 휴대폰**: `npm run build && npm run preview` 후 같은 와이파이의 휴대폰으로 `http://<PC IP>:4173` 접속. iOS Safari 와 Android Chrome 에서 두 손가락 확대, 화면 회전, 주소창 높이 변화(100dvh)를 확인하세요.
3. **오프라인**: 배포된 주소를 한 번 연 뒤 비행기 모드로 새로고침해 보세요. 열리면 서비스 워커가 동작하는 것입니다.
4. **홈 화면 추가**: Android Chrome "앱 설치", iOS Safari "홈 화면에 추가" 로 아이콘과 전체 화면 실행을 확인하세요.
5. **교실 와이파이**: 학생 30명이 동시에 처음 접속해도 0.34MB 라 부담이 적지만, 학교망이 GitHub Pages 를 막는지 수업 전에 확인하세요. 막혀 있으면 교내 서버나 다른 호스팅에 `dist/` 를 올리면 됩니다.

## 서비스 워커 갱신
새 버전을 배포하면 파일 이름 해시가 바뀌어 캐시 이름이 바뀝니다. 이미 앱을 열어 둔 기기는 다음 새로고침 때 새 버전을 받습니다.
